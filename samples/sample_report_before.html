Detailed Findings

1. Git repository exposed High

WR-060 | Sensitive File Exposure

Description: The .git directory is reachable over the web. An attacker can often rebuild the full source code, including history and secrets.

Evidence: http://127.0.0.1:8080/.git/HEAD returned: ref: refs/heads/main

Recommendation: Block access to .git in the web server config and remove it from the web root.

2. Environment file exposed High

WR-061 | Sensitive File Exposure

Description: A .env file is publicly readable. These files usually hold passwords, API keys, and database connection strings.

Evidence: http://127.0.0.1:8080/.env returned key=value content

Recommendation: Remove the .env file from the web root, block it in the server config, and rotate every secret it contained.

3. Password submitted over HTTP High

WR-070 | Forms

Description: A login or password form sends credentials without encryption.

Evidence: Form on http://127.0.0.1:8080/login (POST to http://127.0.0.1:8080/login)

Recommendation: Serve the page and the form action over HTTPS only.

4. Site served over unencrypted HTTP Medium

WR-001 | Transport Security

Description: The application responded over plain HTTP. Traffic, including credentials and session cookies, can be read or modified by anyone on the network path.

Evidence: Final URL: http://127.0.0.1:8080/

Recommendation: Serve the application over HTTPS and redirect all HTTP requests to HTTPS.

5. Missing Content-Security-Policy header Medium

WR-010 | Security Headers

Description: No Content Security Policy was set, so the browser has no restriction on where scripts and other resources can load from. This makes cross-site scripting easier to exploit.

Evidence: Header Content-Security-Policy not present in response

Recommendation: Add a Content-Security-Policy header, starting with something like default-src 'self'.

6. No clickjacking protection Medium

WR-011 | Security Headers

Description: Neither X-Frame-Options nor a CSP frame-ancestors directive was set, so the page can be embedded in a frame on another site and used for clickjacking.

Evidence: X-Frame-Options and CSP frame-ancestors both absent

Recommendation: Add X-Frame-Options: DENY or a CSP frame-ancestors 'none' directive.

7. Insecure cookie attributes: sessionid Medium

WR-030 | Cookie Security

Description: Cookie flags limit how a cookie can be stolen or misused. Secure keeps it off plain HTTP, HttpOnly keeps it away from JavaScript, and SameSite limits cross-site request forgery. The name suggests this is a session cookie.

Evidence: Secure flag missing; HttpOnly flag missing; SameSite attribute missing. Raw header: sessionid=a81b2c; Path=/

Recommendation: Set the cookie with Secure, HttpOnly, and SameSite=Lax or Strict.

8. Overly permissive CORS policy Medium

WR-040 | CORS

Description: Access-Control-Allow-Origin is set to a wildcard, so any website can read responses from this application in a visitor's browser.

Evidence: Access-Control-Allow-Origin: *

Recommendation: Restrict Access-Control-Allow-Origin to a list of trusted origins.

9. Potentially dangerous HTTP methods allowed Medium

WR-051 | HTTP Methods

Description: The server advertises methods that can change or remove content. Verify they require authentication.

Evidence: Allow: GET, POST, PUT, DELETE, OPTIONS, TRACE

Recommendation: Disable methods the application does not need.

10. Directory listing enabled at /uploads/ Medium

WR-064 | Information Disclosure

Description: The server lists directory contents, letting anyone browse files that were never linked.

Evidence: http://127.0.0.1:8080/uploads/ returned an 'Index of' page

Recommendation: Disable directory listing, for example Options -Indexes in Apache.

11. POST form with no visible CSRF token Medium

WR-073 | Forms

Description: No hidden anti-CSRF token field was found. Unless the app protects against CSRF another way, such as SameSite cookies or custom headers, an attacker's site could submit this form as a logged-in user. Verify manually.

Evidence: Form on http://127.0.0.1:8080/login (POST to http://127.0.0.1:8080/login)

Recommendation: Add a per-session or per-request anti-CSRF token to state-changing forms.

18. HTTP TRACE method enabled Low

Evidence: TRACE request returned 200 with the request echoed

Recommendation: Disable TRACE, for example TraceEnable Off in Apache.

19. Missing Permissions-Policy header Info

WR-014 | Security Headers

Description: No Permissions-Policy was set to limit browser features such as camera, microphone, and geolocation.

Evidence: Header Permissions-Policy not present in response

Recommendation: Add a Permissions-Policy header that disables features the site does not use.

20. Password field without autocomplete guidance Info

WR-074 | Forms

Description: The password field has no autocomplete attribute. This is informational; modern guidance prefers current-password or new-password over turning it off.

Evidence: Form on http://127.0.0.1:8080/login (POST to http://127.0.0.1:8080/login)

Recommendation: Set autocomplete="current-password" or "new-password" on password fields.

21. robots.txt lists hidden paths Info

Description: robots.txt tells crawlers which paths to skip, but anyone can read it. Paths listed here are worth reviewing during testing.

Recommendation: Do not rely on robots.txt to hide sensitive areas. Protect them with authentication.
